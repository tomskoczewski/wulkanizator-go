### Conclusions for the top 3 ranked areas

**1. `src/lib/services/` (19 touches, 11 commits)** — never moves alone. 100% of its commits also
touch `context/changes/`; 75% of `src/lib/schemas/` commits land with it; it pairs with
`src/components/appointments/` (5) and `src/pages/api/` (4 as a triple). Reading: a business rule
change here propagates **up** through its zod schema and API route and **out** into the React
island. The unit tests are colocated (`appointments.test.ts`, `slot-suggestions.test.ts`,
`day-plan.test.ts`, `appointment-transitions.test.ts`, `status-failure.test.ts`) — so the tests
travel with the rule, which is the healthy half of this coupling. The unhealthy half is that the
_same_ rule also lives in `supabase/migrations/` (see 3 below), and those two never move in the
same commit.

**2. `src/pages/api/` (19 touches, 6 commits)** — high touches, low commit count: it moves in
**wide, shallow sweeps**. Five of its twelve endpoints were touched twice each in what look like
cross-cutting passes (`bays`, `services`, `working-hours`, `workshop`, `appointment-status`), never
one endpoint at a time. Reading: this is a **uniform surface** — a convention change (validation,
error envelope, auth) rewrites the whole directory at once. That makes it cheap to change
consistently and expensive to change partially; a route that drifts from the convention will not be
caught by "did we touch that file", because the sweeps touch everything anyway.

**3. `src/lib/` direct + `src/` direct (33 touches together)** — `auth-guard.ts` (7),
`middleware.ts` (5) and `types.ts` (8) form the repo's **cross-cutting spine**: 70% of `src/lib`
commits also touch `src/` root, and `src/lib` pairs with `src/pages` (5) and `(root)` (6). Reading:
these three files are where a change stops being local. `auth-guard.ts` + `middleware.ts` co-move
because the route table and its enforcement are one decision split over two files, and `types.ts`
gets dragged in by anything that adds a DTO. This is the highest-blast-radius cluster in the repo.

### Two more couplings worth naming

- **`supabase/migrations` + `supabase/tests` (5 commits, always with `context/changes`)** — schema
  and its pgTAP RLS proof move as one unit. Good discipline; it also means `rls_workshop_scope.test.sql`
  is a bottleneck file that every schema change re-opens (hence its 821-line churn).
- **`context/archive` + `context/foundation` (8 co-commits, 80%)** — archiving a change is also when
  `roadmap.md` / `lessons.md` get updated. The workflow's closing ritual, visible in the history.

**Answer: there are two, one per side of the repo.**

  services, components and schemas alike. It is the repo's shared vocabulary (entities + DTOs) and

  shape the prompt is looking for — no logic, maximum reach.

  every recurring rule lands in `AGENTS.md`. Since `AGENTS.md` is loaded into every agent session,
  it is a **behavioural** common denominator: editing it changes how future work is done everywhere.

Not a common denominator, despite looking like one: `src/db/database.types.ts` — it is generated,
was filtered out as noise, and would otherwise have dominated this table for the wrong reason.

## 6. Limitations (carry these into artifacts 2–4)

- **Window is 3 months, not 12.** 109 commits total; every count here is small-sample. A file with
  8 commits and one with 7 are not meaningfully different in rank.
- **Solo repo.** 109/109 commits by one person under two git identities. Nothing in this artifact
  says anything about team territory — that is artifact 3's problem to handle honestly.
- **July is empty.** The "quarterly emphasis shift" the prompt expects is really a bootstrap → one
  intense month → hardening sequence, and the month boundaries do the work that quarters cannot.
- **Merge commits contribute no files.** 3 merge commits (GitHub web UI) show empty `--name-only`;
  their content is already counted via the individual commits on `main`.
- **`--all` vs `main`.** 17 commits live on unmerged branches (`chore/audit-fix`,
  `tracker-status-sync`, `backup/main-pre-drop`, `docs/mvp-check-cleanup`) and are excluded.
  Work that was explored and abandoned there is invisible here.
- **Touches ≠ effort.** Commit counts and line churn disagree (see §1d); the `settings/` components
  are large and barely revisited, the pgTAP suite is both. Neither metric alone locates risk.
- **Unknown, not "unconnected": `.astro` files.** 14 `.astro` files in `src/` (every page and
  layout) are invisible to `dependency-cruiser`, which matters from artifact 2 onward. Git history
  _does_ see them, so `dashboard.astro` and `AppShell.astro` appear here — expect them to vanish
  from the dependency graph. That is a tooling gap, not an absence of coupling.

## Reproduce

```bash
# raw material
git log --format='C%H|%ad' --date=short --name-only > raw.txt

# top files (after the noise filter listed above)
git log --format='' --name-only | grep -vE 'package-lock|database\.types|^dist/|^test-results/' \
  | sort | uniq -c | sort -rn | head -20

# line churn, code only
git log --numstat --format='' -- src supabase e2e \
  | awk 'NF==3 && $1!="-" {c[$3]+=$1+$2} END {for (f in c) printf "%6d %s\n", c[f], f}' \
  | sort -rn | head -20

# renames / deletions (why a "hot" file is missing today)
git log -M -C --diff-filter=RCD --name-status --format='%h|%ad|%s' --date=short
```

Directory aggregation, co-change pairs/triples and the distinct-area metric were computed with a
throwaway Python pass over `raw.txt` (parse `C<sha>|<date>` headers, filter noise, collapse
`context/{changes,archive}/*`, then `itertools.combinations` over the per-commit area set).
